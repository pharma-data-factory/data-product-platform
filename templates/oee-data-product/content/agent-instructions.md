## 4. Requirements Traceability

Every test, feature, and implementation decision should be traceable to a
requirement. The approved requirements are in `urs.yaml`. Reference them in:

- Test function names and docstrings: `# Satisfies: URS-EPM-001`
- PR descriptions: "This addresses requirement URS-EPM-003"
- Commit messages: `feat(domain): satisfy URS-EPM-004`

The platform CI gate checks traceability coverage. Tests without requirement
references do not count toward the validation coverage score.

## 5. Contracts — What You Must Honour

The data contracts in `contracts/` define the data interfaces this product
provides and consumes. Your implementation must produce and accept exactly
what the contracts specify:

- Field names and types as declared

Contract violations are caught by the CI Contract Tests stage.

## 6. Security — Non-negotiable

- Never commit secrets, API keys, passwords, or tokens — not even in comments
- Configuration goes in `.env` (gitignored) — see `dataprod/settings.py` for the schema
- Platform components (MQTT, REST API, Health) handle authentication — do not bypass them
- `type: secret` configuration keys are marked in `composition.yaml` — never log them
