# ${{ values.name }}

${{ values.description }}

Generated by the Data Product Platform **REST Equipment Data Product** Golden Path.

This data product fetches equipment master data from a configurable REST
source, validates it against a versioned data contract, stores records in
SQLite, and exposes a REST API plus a quality gate. The same `equipmentId`
updates the stored record instead of creating a duplicate.

A real SAP, MES, or customer system is not required. Leave `SOURCE_API_URL`
empty and use `POST /api/v1/equipment` for local mock ingestion.

## Requirements

- Python 3.12+
- Docker (optional)

## Data contract

Version: `1.0.0`

Canonical schema: `contracts/equipment-event.schema.json`

```json
{
  "equipmentId": "EQ-1001",
  "name": "Bioreactor 01",
  "site": "SITE-A",
  "status": "ACTIVE",
  "updatedAt": "2026-08-17T06:30:00Z"
}
```

Contract rules:

- `equipmentId` is a unique non-empty string
- `name` is a non-empty string
- `site` is a non-empty string
- `status` must be `ACTIVE`, `INACTIVE`, or `MAINTENANCE`
- `updatedAt` is an ISO-8601 datetime

Repeated ingestion of the same `equipmentId` updates the record.

## Data quality

Mandatory quality checks:

- `equipmentId` is present and not empty
- `equipmentId` is unique
- `name` is present and not empty
- `site` is present and not empty
- `status` is a valid enum value
- `updatedAt` is a valid ISO-8601 datetime
- no malformed records (contract schema)

If a mandatory check fails, `GET /api/v1/quality` returns `"status": "FAIL"` and
CI fails.

## API

### `GET /health`

```json

  "status": "UP",
  "service": "${{ values.name }}",
  "version": "${{ values.version }}"
}
```

### `GET /api/v1/equipment`

Returns stored equipment records.

### `POST /api/v1/equipment`

Local mock ingestion path. Returns `201` for a new `equipmentId` and `200`
when the same `equipmentId` is updated.

```bash
curl -X POST http://localhost:8080/api/v1/equipment ^
  -H "Content-Type: application/json" ^
  -d "{\"equipmentId\":\"EQ-1001\",\"name\":\"Bioreactor 01\",\"site\":\"SITE-A\",\"status\":\"ACTIVE\",\"updatedAt\":\"2026-08-17T06:30:00Z\"}"
```

### `POST /api/v1/source/sync`

Fetches records from `SOURCE_API_URL` when configured. Disabled when the URL
is empty.

## REST source

Configuration comes from environment variables. Do not commit secrets.

| Variable | Purpose |
| --- | --- |
| `SOURCE_API_URL` | External equipment API. Empty disables source fetch. |
| `SOURCE_API_TOKEN` | Optional bearer token |
| `SOURCE_API_TIMEOUT` | HTTP timeout in seconds. Default `10`. |

The source client accepts a JSON array or `{ "items": [ ... ] }`.

## Quality gate (CI)

GitHub Actions fails the pipeline if any mandatory quality check fails:

1. Lint
2. Unit tests
3. Contract tests
4. Data quality tests
5. Compatibility tests
6. Docker build

Compatibility tests fail CI when a breaking contract change would affect an
active consumer such as `equipment-dashboard-consumer` (`1.x`).
