# ${{ values.name }}

${{ values.description }}

Generated by the Data Product Platform **MQTT Temperature Data Product** Golden Path.

This data product ingests temperature events from MQTT, validates them against a
versioned data contract, stores recent readings in SQLite, and exposes a REST
API plus a quality gate. Ingest is idempotent on `eventId`.

## Requirements

- Python 3.12+
- Docker (optional)

## Data contract

Version: `1.1.0`

Canonical schema: `contracts/temperature-event.schema.json`

```json
{
  "eventId": "evt-probe-1",
  "deviceId": "probe-1",
  "timestamp": "2026-08-16T17:00:00Z",
  "temperature": 21.5,
  "unit": "C"
}
```

Contract rules:

- `eventId` is a unique non-empty string
- `deviceId` is a non-empty string
- `timestamp` is an ISO-8601 datetime
- `temperature` is a number
- `unit` must be `C` or `F`

A duplicate `eventId` does not create a second stored event.

## Data quality

Mandatory quality checks:

- `eventId` is not empty
- `deviceId` is not empty
- `timestamp` is a valid ISO-8601 datetime
- `temperature` is within configurable technical limits (`TEMPERATURE_MIN` / `TEMPERATURE_MAX`)
- `unit` is `C` or `F`

If a mandatory check fails, `GET /api/v1/quality` returns `"status": "FAIL"` and
CI fails.

Default technical limits: `-50` to `150`.

## API

### `GET /health`

```json
{
  "status": "UP",
  "service": "${{ values.name }}",
  "version": "${{ values.version }}"
}
```

### `GET /api/v1/temperatures`

Returns recent stored temperature events.

### `POST /api/v1/temperatures`

Stores a temperature event without an MQTT broker. Returns `201` for a new
`eventId` and `200` when the same `eventId` is replayed.

```bash
curl -X POST http://localhost:8080/api/v1/temperatures ^
  -H "Content-Type: application/json" ^
  -d "{\"eventId\":\"evt-probe-1\",\"deviceId\":\"probe-1\",\"timestamp\":\"2026-08-16T17:00:00Z\",\"temperature\":4.2,\"unit\":\"C\"}"
```

## MQTT

Configuration comes from environment variables:

| Variable | Purpose |
| --- | --- |
| `MQTT_HOST` | Broker host. Empty disables MQTT ingestion. |
| `MQTT_PORT` | Broker port. Default `1883`. |
| `MQTT_USERNAME` | Optional username |
| `MQTT_PASSWORD` | Optional password |
| `MQTT_TOPIC` | Subscription topic. Default `${{ values.mqttTopic }}`. |
| `TEMPERATURE_MIN` | Lower technical quality limit. Default `-50`. |
| `TEMPERATURE_MAX` | Upper technical quality limit. Default `150`. |

## Quality gate (CI)

GitHub Actions fails the pipeline if any mandatory quality check fails:

1. Lint
2. Unit tests
3. Contract tests
4. Data quality tests
5. Compatibility tests
6. Docker build

Compatibility tests fail CI when a breaking contract change would affect an
active consumer such as `temperature-dashboard-consumer` (`1.x`).
